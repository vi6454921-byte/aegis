# Аегис — Telegram-бот для разбора задач по начерталке и вышмату

Бот принимает заказы (фото условия → количество задач → дедлайн → конспекты → комментарий) и заявки на
объяснение темы по фото лекции или практики, считает цену с наценкой за срочность и скидками, выставляет счёт
(тестовые деньги, Telegram Stars или перевод с проверкой чека), выдаёт решение как Mini App прямо в Telegram,
ведёт балансы, бонусы со сроком жизни, бонусы за подписку на канал и реферальную программу, новичкам дарит
ссылки на бесплатные тренажёры. Клиенты пишут в поддержку прямо в боте (забаненные — чтобы обжаловать бан), админы отвечают свайпом. Бот везде говорит от лица
команды: «мы проверим», «пришлём».
Внутри — админ-панель `/admin` с двумя уровнями доступа: заказы, обращения, чеки, задания, пользователи и
Excel-таблица, рассылки, настройки, бэкапы и экспорт; у админов 2 уровня — блок «🔐 Управление» (админы, бан,
«Приоритет» и «Месяц бесплатно», выдача денег, промокоды, запросы к БД). Клиенты могут заработать рубли на балансе за
задания «📌 Ссылка в профиле» и «📣 Пост о нас». `/commands` показывает каждому только его команды.
С 2.3 — промокоды на безлимит (все заказы бесплатно), черновики заказа, которые не теряются, «📥 Входящие» и
чат админа с клиентом по заказу («✉️ Ответить»).

> **Самый простой запуск — в файле `START_HERE.txt`**: установить Python и дважды щёлкнуть
> `start_windows.bat` (Windows) или `start_mac.command` (Mac). Токен лежит в `.env` (в архиве 2.3 он уже
> вписан), админом становишься командой `/admin КОД` — код бот покажет в своём окне при запуске.

Стек: Python 3.12+, aiogram 3, SQLAlchemy 2 (async) + SQLite, Alembic, aiohttp (Mini App), APScheduler,
Docker + Caddy (HTTPS).

4. Проверь: `/admin → 🔐 Управление → 🎟 Промокоды` — «Всего 45 · свободно 45», на главном экране —

5. Убери `promo_codes.txt` в надёжное место (это как пароли; в git и docker-образ файл не попадает) и раздавай

На VPS: `cd /opt && unzip -o aegis_bot_v2_3.zip -x 'aegis/.env' 'aegis/promo_codes.txt' && cd aegis && docker compose up -d --build`
— `data/` в архиве нет, серверный `.env` (с доменом) не перезаписывается, а файл с промокодами серверу не нужен
(коды уже в базе). Если на сервере другой токен — впиши `BOT_TOKEN` и `BOT_USERNAME` в `/opt/aegis/.env` и
выполни `docker compose up -d`. С более старых версий (2.0, 2.1) — так же: недостающие миграции применятся одна за
другой.

Меняются в `⚙️ Настройки → 🎁 Подарки (ссылки)`: пришли новую ссылку, `-` — скрыть подарок. Кнопки подарков в уже отправленных сообщениях не ломаются — присылают актуальные ссылки |

приветствия, подставится новый — с подарками-ссылками; если менял, твой текст сохранится, а подарки
добавятся в его конец (или туда, где стоит `{gifts}`). Папку `data/static/gifts/` можно удалить — она больше
не нужна. Со второй версии можно сразу на 2.3 — миграции `0003`–`0005` применятся одна за другой.

## 2. Бот в @BotFather и команды

1. Открой [@BotFather](https://t.me/BotFather) → `/newbot` → имя (например, «Аегис») → юзернейм на `bot`
   (например, `aegis_samara_bot`). BotFather пришлёт **токен** — это пароль бота.
2. Оформление (по желанию): `/setuserpic` — аватар, `/setdescription` — текст на пустом экране чата,
   `/setabouttext` — короткое «о боте».
3. **Команды бот выставляет сам при запуске**, вручную ничего делать не нужно. Меню команд у каждой роли
   своё: клиент видит только команды «для всех», админ 1 уровня — ещё и свои, 2 уровень и владелец — все
   доступные им. Меню обновляется само, когда админа назначают, повышают, понижают или снимают. Команда
   `/commands` (и `❓ Помощь → ⌨️ Команды`) показывает тот же список с описаниями — только доступное этому
   человеку.

   **Для всех:**

   | Команда | Что делает |
   |---|---|
   | `/start` | приветствие со ссылками на подарки, главное меню (по реф-ссылке — засчитывает приглашение) |
   | `/help` | как всё устроено: сроки и цены, бонусы и задания, гарантия, оплата, поддержка, команды |
   | `/guide` | короткая обучалка (5 экранов; новичкам показывается сама при первом `/start`) |
   | `/terms` | условия работы (их принимают один раз перед первым заказом) |
   | `/support` | написать в поддержку — сообщение придёт всем админам, ответ придёт сюда же |
   | `/paysupport` | вопрос по оплате (Telegram требует такую команду у ботов с платежами) |
   | `/commands` | все команды, которые доступны тебе |
   | `/cancel` | отменить текущее действие |

   **Админам** (работают только у админов — права проверяются при каждой команде; у остальных бот отвечает,
   что команда только для админов):

   | Команда | Кто | Что делает |
   |---|---|---|
   | `/admin` | 1 и 2 уровень | админ-панель: владелец — id в `ADMIN_IDS` или назначен через `/admin КОД`, остальные — из «👮 Админы» |
   | `/user @username` или `/user ID` | 1 и 2 уровень | карточка пользователя |
   | `/give @username 500` | 2 уровень | выдать рубли; `-500` — списать; можно по ID, с копейками (`99,50`) и комментарием после суммы. Коротко — сообщением `@username +500` / `@username -500` |
   | `/ban @username причина`, `/unban @username` | 2 уровень | бан с причиной и разбан (с подтверждением и уведомлением; админов и себя забанить нельзя) |
   | `/priority @username` | 2 уровень | выдать или снять «Приоритет» |
   | `/freemonth @username 30 10` | 2 уровень | «Месяц бесплатно»: дней и задач (без чисел — выбор кнопками, `off` — отключить) |
   | `/addadmin @username`, `/removeadmin @username` | 2 уровень | назначить или снять админа 1 уровня (по нику или ID, с подтверждением; ссылка-приглашение — в «👮 Админы»). Владелец: `/addadmin @username 2` — назначить 2 уровень; снять может любого, кроме владельцев, в том числе закреплённого 📌 |
   | `/db` | 2 уровень | 🗄 запросы к БД: файл базы, выгрузки, готовые отчёты |
   | `/backup` | 2 уровень | свежий бэкап базы файлом в чат |

   Команды 2 уровня без аргументов открывают нужный экран с кнопками.

   Если хочешь задать общий список и в BotFather: `/setcommands` → выбери бота → вставь (бот всё равно
   перезапишет его своим при запуске):
   ```
   start - Главное меню
   help - Как это работает
   guide - Как пользоваться ботом
   terms - Условия
   support - Написать в поддержку
   paysupport - Вопрос по оплате
   commands - Все доступные мне команды
   cancel - Отменить текущее действие
   ```
4. Для Telegram Stars ничего подключать не нужно — ни платёжного провайдера, ни токена оплаты.

> ⚠️ Токен никому не показывай. Если он попал на скриншот или в чужой чат — в @BotFather: `/revoke` → выбери
> бота → получишь новый токен, впиши его в `.env` и перезапусти бота. Старый сразу перестанет работать.

**Админ без поиска своего id.** Если `ADMIN_IDS` пуст, при запуске бот пишет в консоль (в Docker — в
`docker compose logs bot`) строку `/admin 123456` со случайным кодом. Отправь её боту — станешь админом;
id сохранится в базе и сам впишется в `ADMIN_IDS` в `.env`. Код одноразовый, после 10 неверных попыток
бот выдаёт новый. Если `ADMIN_IDS` в `.env` заполнен, кодов нет и действует только он.

**Свой Telegram id** (если хочешь вписать `ADMIN_IDS` вручную): напиши [@userinfobot](https://t.me/userinfobot) —
он ответит числом `Id`.

## 3. Файл .env

В архиве 2.3 `.env` уже есть: в нём токен (`BOT_TOKEN`) и `BOT_USERNAME=aegis_samara_bot`, остальное — как в
`.env.example`. Токен хранится **только** в `.env`: его нет в коде, `.env.example`, README и тестах, а в логах
он заменяется на `***`. Не публикуй `.env` и не коммить его (он в `.gitignore`); токен утёк — `/revoke` в
@BotFather и новый токен в `.env`. Если файла нет совсем — `cp .env.example .env` и впиши `BOT_TOKEN`.

Минимум для запуска: `BOT_TOKEN` (админа можно назначить кодом, см. выше). Для Mini App ещё `DOMAIN` и `WEBAPP_BASE_URL`
(раздел 6). Остальное — стартовые значения с комментариями прямо в `.env.example`.

Цены, срочность, скидки, лимиты, бонусы, канал, режим оплаты, реквизиты, задания за рубли, тексты приветствия и
`/terms` меняются на лету в `/admin → ⚙️ Настройки`; значение из админки главнее значения из `.env`.

**Закреплённые админы 2 уровня (с 2.2):**

```
SENIOR_ADMIN_USERNAMES=badVInq,dimaslavikov1
SENIOR_ADMIN_IDS=
```

- `SENIOR_ADMIN_USERNAMES` — ники без `@` через запятую, регистр не важен. Если строки в `.env` нет, действует
  значение по умолчанию — `badVInq,dimaslavikov1`. Пустое значение (`SENIOR_ADMIN_USERNAMES=`) — никого не
  закреплять по нику.
- `SENIOR_ADMIN_IDS` — необязательно: числовые id через запятую, если они известны. Такие люди закрепляются
  сразу при запуске, без ожидания `/start`.
- После изменения `.env` перезапусти бота. Убрал ник или id из `.env` — при запуске закрепление снимается и
  доступ к админке у этого человека пропадает (владельцам придёт сообщение). Подробнее — раздел 8,
  «Закреплённые админы 📌».

## 4. Запуск локально

Нужен Python 3.12 или новее. Проще всего — двойной щелчок по `start_windows.bat` / `start_mac.command`:
скрипт сам создаст `.venv`, поставит зависимости (только при первом запуске) и запустит бота. Вручную:

```bash
cd aegis
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m app
```

В логе появится `Аегис запущен: @твой_бот | оплата: test | …`. Напиши боту `/start`, затем `/admin`.

Без `WEBAPP_BASE_URL` всё работает, только решения приходят HTML-файлами (открываются в браузере телефона);
подарки — обычные ссылки, им домен не нужен. Чтобы проверить Mini App на своём компьютере, нужен публичный
HTTPS-адрес, например `cloudflared tunnel --url http://localhost:8080` → вписать выданный
`https://….trycloudflare.com` в `WEBAPP_BASE_URL`. Адрес туннеля меняется при каждом запуске — для постоянной
работы нужен VPS с доменом.

Остановить — `Ctrl+C`. Одновременно может работать только **один** экземпляр бота с этим токеном.

## 5. Запуск на VPS (Docker)

Подойдёт любой VPS с Ubuntu 22.04/24.04 и 1 ГБ памяти.

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. Проект (с компьютера): scp aegis_bot_v2_3.zip root@IP_СЕРВЕРА:/opt/
cd /opt && unzip aegis_bot_v2_3.zip -x 'aegis/promo_codes.txt' && cd aegis   # промокоды серверу не нужны

# 3. Настройки
cp -n .env.example .env && nano .env # BOT_TOKEN уже вписан; для Mini App — DOMAIN и WEBAPP_BASE_URL

# 4. Порты для HTTPS (если включён ufw)
ufw allow 80/tcp && ufw allow 443/tcp

# 5. Запуск (бот + Caddy с HTTPS)
docker compose up -d --build
docker compose logs -f bot            # ждём «Аегис запущен» (и код /admin, если админ ещё не назначен)
```

Без домена можно запустить только бота: `docker compose up -d --build bot`.

Полезное:

| Что | Команда |
|---|---|
| логи | `docker compose logs -f bot` |
| перезапуск | `docker compose restart bot` |
| остановить / запустить | `docker compose stop` / `docker compose start` |
| обновить код | `cd /opt && unzip -o aegis_bot_vX_Y.zip -x 'aegis/.env' 'aegis/promo_codes.txt' && cd aegis && docker compose up -d --build` (папки `data/` и `.env` не трогаются) |
| статус и healthcheck | `docker compose ps` |

Бот сам перезапускается после падения и перезагрузки сервера (`restart: unless-stopped`). Миграции БД
применяются автоматически при каждом старте.

## 6. Домен и HTTPS для Mini App

Telegram открывает Mini App только по **HTTPS** с настоящим сертификатом. Его автоматически получает Caddy
из `docker-compose.yml`.

1. Купи домен или используй поддомен (например, `aegis.example.ru`).
2. В DNS добавь **A-запись**: `aegis.example.ru → IP сервера`. Подожди, пока заработает
   (`ping aegis.example.ru` показывает IP сервера).
3. В `.env`:
   ```
   DOMAIN=aegis.example.ru
   WEBAPP_BASE_URL=https://aegis.example.ru
   ```
4. `docker compose up -d --build` — Caddy выпустит сертификат Let's Encrypt (порты 80 и 443 должны быть
   открыты) и будет продлевать его сам.
5. Проверка: `https://aegis.example.ru/health` в браузере → `ok`.

Решения открываются по `https://домен/s/{токен}` (токены — `secrets.token_urlsafe(24)`, чужое решение не
угадать; после возврата денег решение закрывается). Старые ссылки подарков `https://домен/g/{токен}` из прошлых
версий перенаправляют на текущие ссылки из настроек. В BotFather для этого ничего настраивать не нужно.

> ⚠️ **Не меняй `WEBAPP_BASE_URL` после запуска** — кнопки «🧩 Открыть решение» в уже отправленных сообщениях
> ведут на этот адрес и перестанут открываться. При переезде на другой сервер просто перенаправь тот же домен
> на новый IP (раздел 10).

## 7. Оплата: тест, Telegram Stars или перевод

Режим — в `/admin → ⚙️ Настройки → 💳 Оплата → «Режим оплаты»`. Менять его может только админ 2 уровня, каждое
переключение — с подтверждением, перезапуск не нужен. Текущий режим виден на главном экране админки; пока включён
тест, там же есть кнопка «⭐ Включить оплату звёздами».

**🧪 Тест** (по умолчанию) — воображаемые деньги: счёт выглядит как настоящий, вместо оплаты кнопка
«💳 Оплатить (тест)». Всё тестовое помечено 🧪 и в статистике считается отдельно от реальной выручки.

**⭐ Telegram Stars** — оплата звёздами (валюта XTR). Цена в звёздах = рубли / `RUB_PER_STAR`, с округлением
вверх. Возврат звёздами делается кнопкой в карточке заказа (`refundStarPayment`), либо деньги можно вернуть
на рублёвый баланс в боте.

**🏦 Перевод (ручная проверка)** — клиент получает счёт с твоими реквизитами (карта, СБП — что впишешь),
переводит сумму, жмёт «✅ Я оплатил — отправить чек» и присылает скрин или PDF. Всем админам приходит
«🧾 Чек об оплате» с кнопками «✅ Оплата пришла» / «❌ Не пришла» — это может сделать и админ 1 уровня. После
подтверждения заказ встаёт в очередь как обычно, при «❌ Не пришла» клиенту приходит просьба проверить перевод.
Чек не проверили за час — бот напомнит админам; все непроверенные чеки — в `/admin → 🧾 Чеки`. Реквизиты
задаются в `⚙️ Настройки → 💳 Оплата → «Реквизиты для перевода»`; пока их нет, на главном экране админки висит
предупреждение. Это реальные деньги — в статистике они идут вместе со Stars.

### Как включить настоящую оплату

1. Прогони проверку на двух аккаунтах (раздел 13) в режиме test.
2. Для перевода сначала впиши `⚙️ Настройки → 💳 Оплата → «Реквизиты для перевода»` — без них бот перевод не
   включит. Для звёзд ничего не нужно; курс «₽ за 1 звезду» и пакеты пополнения — там же, в «💳 Оплата».
3. `/admin → ⭐ Включить оплату звёздами` (или `«Режим оплаты» → 🏦 Включить оплату переводом`). Бот покажет,
   что уберётся, — нажми «✅ Да, включить звёзды» («✅ Да, включить перевод»).

Тестовая оплата при этом исчезает полностью:
- все новые счета — только звёздами (или переводом), кнопка «💳 Оплатить (тест)» больше нигде не появляется;
- неоплаченные тестовые счета отменяются. Нажмёт клиент старую кнопку — бот ответит «Этот счёт уже не
  действует» и уберёт её; клиент открывает заказ в «📦 Мои заказы» и платит заново, уже по-настоящему;
- тестовые деньги, что ещё лежат на балансах (рубли и бонусы из тестовых оплат), списываются — ими нельзя
  оплатить настоящий заказ. В истории клиента это строка «Тестовые деньги убраны — включена настоящая оплата».
  Настоящие рубли и бонусы не трогаются;
- тестовые заказы и история остаются с пометкой 🧪 — удалить их можно кнопкой «🧹 Удалить тестовые данные» на
  экране режима или в `💾 Данные → 🧹 Очистить тестовые данные` (перед этим нажми «💾 Бэкап сейчас»; скрипт
  `scripts/clear_test_data.py` делает бэкап сам). Балансы пересчитаются по журналу, реальные данные не трогаются.

**Вернуть тест** — `«Режим оплаты» → 🧪 Вернуть тестовую оплату → ✅ Да, вернуть тест`. Новые счета снова
тестовые; уже выставленные счета в звёздах остаются действительными — если клиент оплатит, деньги зачислятся.
Пока включён тест, любой клиент может «оплатить» заказ воображаемыми деньгами, поэтому включай его только для
проверки. Между звёздами и переводом можно переключаться напрямую: «⭐ Перейти на звёзды» / «🏦 Перейти на
перевод».

Можно и через `.env` (`PAYMENTS_MODE=stars` или `manual`), но только если режим ещё ни разу не меняли в
админке — значение из админки главнее. Если бот запускается в настоящем режиме, а тестовые счета или деньги ещё
остались (например, режим сменили в `.env` или в прошлой версии бота), он уберёт их сам при старте и напишет об
этом в лог.

Выплата звёзд: @BotFather → бот → Payments / Balance (вывод через Fragment), подробности —
https://core.telegram.org/bots/payments-stars.

## 8. Админ-панель

`/admin` (или кнопка «🛡 Админка» внизу) открывает экран **«Требует внимания»**: сколько заказов ждут проверки
и счёта, сколько чеков, оплаченных заказов без исполнителя, споров «не зачли», сообщений без ответа и заявок по
заданиям (а «📥 Входящие» — всё необработанное одним списком, новые сверху); ниже — что в работе, ближайший дедлайн, состояние приёма и режим оплаты, а также предупреждения (нет
реквизитов, бот не может проверять подписку на канал). У админа 2 уровня под ними — блок
**«🔐 Управление (2 уровень)»**. Доступ проверяется на каждом нажатии и каждой команде (а не только скрытием
кнопок), все действия пишутся в `admin_log`. «❓ Справка» на главном экране — короткая шпаргалка по работе,
`/commands` — все команды твоего уровня.

### Уровни админов

| | 1 уровень · оператор | 2 уровень · старший |
|---|---|---|
| 📥 заказы: проверка конспектов, количество задач, счёт, «Взять в работу», решение, «Готово», «Переделать» | ✅ | ✅ |
| 🧾 подтвердить или отклонить оплату переводом | ✅ | ✅ |
| 📨 обращения: читать, отвечать, закрывать; писать клиенту | ✅ | ✅ |
| уведомления о новых заказах, оплатах, чеках и обращениях | ✅ | ✅ |
| 👥 карточки пользователей (`/user`), «✉️ Написать» клиенту | ✅ | ✅ |
| 🎯 задания: «✅ Начислить» за ссылку в профиле, «✅ Принять» пост, подтвердить просмотры, «❌ Отклонить», «🗑 Пост удалён» | ✅ | ✅ |
| ✏️ ручная корректировка начислений по посту | — | ✅ |
| 📊 статистика, 📣 рассылки, ⚙️ настройки, 💾 данные и бэкапы (`/backup`) | — | ✅ |
| 💸 выдать и списать рубли (кнопкой, `/give`, `@username +500`), возвраты, ручная цена, ➕/➖ бонусы | — | ✅ |
| ⭐ «Приоритет», 🎟 «Месяц бесплатно», 🚫 бан и разбан (`/priority`, `/freemonth`, `/ban`, `/unban`) | — | ✅ |
| 🗄 запросы к БД (`/db`), 📊 Excel-таблица пользователей | — | ✅ |
| 👮 Админы: назначить, пригласить и снять админа 1 уровня (`/addadmin`, `/removeadmin`) | — | ✅ |

**Владельцы** — id из `ADMIN_IDS` или тот, кто стал админом через `/admin КОД`. Они всегда на 2 уровне, из бота
не снимаются и только они назначают и снимают админов 2 уровня. Админ 2 уровня, который не владелец,
управляет только админами 1 уровня. У 1 уровня кнопок 2 уровня нет вовсе, а если нажать старую кнопку или
набрать команду вручную, бот ответит «⛔ Недостаточно прав».

**Как добавить помощника:** `/admin → 👮 Админы → ➕ Пригласить: 1 уровень` (владельцу доступно и
«➕ 2 уровень») → бот пришлёт ссылку `https://t.me/бот?start=adm_…`. Перешли её помощнику: он открывает
ссылку, жмёт «Запустить» — и сразу получает доступ и команду `/admin`. Ссылка одноразовая и действует 24 ч.
Ещё вариант — «🔍 Добавить по id / @username» или команда `/addadmin @username` (человек должен хотя бы раз
нажать `/start` в боте). В карточке админа — «⬆️ Сделать 2 уровнем» / «⬇️ Сделать 1 уровнем» (только владелец)
и «🗑 Снять доступ». Меню команд в Telegram у человека меняется сразу.

### Закреплённые админы 📌

@badVInq и @dimaslavikov1 закреплены на 2 уровне через `.env` (`SENIOR_ADMIN_USERNAMES`, раздел 3).

- Пока человек не написал боту, в «👮 Админы» он виден с меткой 📌 и статусом «ожидает /start».
- Как только он впервые пишет боту (`/start` или любое сообщение), бот привязывает его числовой Telegram id:
  ему сразу открываются админка и меню команд 2 уровня, владельцам приходит «📌 Закреплён админ 2 уровня:
  @ник, id …».
- После привязки права определяются только по id. Сменил ник — права остались; кто-то другой занял этот ник —
  прав он не получит, а владельцам придёт «⚠️ Попытка подмены закреплённого админа» (и запись в лог). Каждый ник
  привязывается один раз.
- Понизить или снять закреплённого не могут ни другие админы 2 уровня, ни приглашения. Снять закрепление можно
  двумя способами: убрать ник (или id) из `.env` и перезапустить бота — или владелец в карточке админа жмёт
  «⬇️ Сделать 1 уровнем» / «🗑 Снять доступ». Вернуть снятое владельцем закрепление — кнопка
  «📌 Вернуть закрепление» в «👮 Админы».
- Если числовой id известен заранее, его можно вписать в `SENIOR_ADMIN_IDS` — тогда человек закрепляется при
  запуске, без ожидания `/start`.

### 🔐 Управление (2 уровень)

Блок кнопок на главном экране `/admin` — его видят и нажимают только админы 2 уровня:

- **👮 Админы** — назначить админа 1 уровня по @username, по ID или одноразовой ссылкой, понизить, снять
  (`/addadmin`, `/removeadmin`).
- **⭐ Приоритет / 🎟 Месяц** — найти пользователя по @username или ID → выдать или снять «Приоритет»;
  «Месяц бесплатно» — выбрать число дней и задач (`/priority`, `/freemonth @username 30 10`). Подтверждение,
  пользователь получает уведомление.
- **🚫 Бан / разбан** — по @username или ID, причина кнопкой или своя, подтверждение, уведомление
  (`/ban @username причина`, `/unban @username`). Админов и себя забанить нельзя.
- **💸 Деньги** — выдать или списать рубли: найти по @username или ID → сумма (`500`, `-500`, `99,50`, можно
  сразу с комментарием: `-50 ошибка в заказе`) → комментарий или «Без комментария» → подтверждение. То же — из
  карточки пользователя («💸 Выдать / списать ₽»), командой `/give @username 500` или коротким сообщением боту
  `@username +500` / `@username -500`. Верхнего предела нет — бот проверяет только, что сумма помещается в
  хранилище (64-битное целое в копейках); больше порога из настроек (10 000 ₽) — второе подтверждение
  «⚠️ Большая сумма — проверь нули». Списание не уводит баланс ниже нуля. Клиенту приходит «💰 На баланс
  зачислено N ₽» (комментарий — если включено в настройках). Пользователь ещё не нажимал `/start` — бот так и
  скажет. Каждая операция — в журнале денег и `admin_log` (кто, кому, сколько, комментарий), повторное нажатие
  кнопки подтверждения деньги второй раз не проводит.
- **🗄 Запросы к БД** (`/db`) — 💾 файл базы (свежий бэкап через SQLite backup API, `/backup`), 📤 CSV и
  📊 Excel, готовые отчёты только для чтения: 👤 пользователь (балансы, заказы, друзья, начисления за задания и
  от админов), 📦 последние заказы, 💳 платежи и начисления, 📋 что ждёт модерации. Произвольного SQL и
  изменений через этот раздел нет; каждый запрос пишется в `admin_log`.
- **🎟 Промокоды** — коды на безлимит и безлимит у пользователей, см. «Промокоды на безлимит» ниже.
- **📊 Статистика, 📣 Рассылка, ⚙️ Настройки, 💾 Данные** — как раньше (в статистике с 2.3 — строка
  «♾ Безлимит (не выручка)»).

### Задания за рубли: «📌 Ссылка в профиле» и «📣 Пост о нас»

Клиент находит их в «💰 Баланс → 🎁 Бонусы и акции» (или «❓ Помощь → 🎁 Бонусы и акции»). Награды —
**обычные рубли** на рублёвом балансе: не сгорают, не ограничены лимитом оплаты бонусами и оплачивают заказ
целиком. В истории клиента видно, за что начислено. Всё начисляется через журнал денег, поэтому проверка
целостности сходится.

**📌 Ссылка в профиле — 100 ₽, один раз на аккаунт.** Клиент видит свою реферальную ссылку (нажатием
копируется; переходы по ней засчитываются как приглашения) и инструкцию: Настройки → Изменить профиль →
О себе (Bio) → вставь ссылку → сохрани. Затем «✅ Я добавил — отправить скрин» → фото (или картинка файлом).
Всем админам 1 и 2 уровня приходит карточка: скрин, пользователь, подсказка бота — есть ли ссылка на бота в
bio («✅ найдена», «⚠️ не найдена» или «не удалось проверить»; решает всё равно админ) — и кнопки «✅ Начислить» /
«❌ Отклонить» (причина кнопкой или своя). Как с чеками: решил один — у остальных карточка помечается. Пока заявка на проверке, новую подать нельзя;
после отказа — можно снова; забаненным не начисляется. Перепроверка (`«Перепроверить ссылку через, дней»`,
0 — выкл): если через N дней ссылки в bio нет, награда списывается (не ниже нуля) с уведомлением.

**📣 Пост о нас — 200 ₽ + 100 ₽ за каждые 100 просмотров.** Клиент выбирает «📣 Telegram-канал» или
«🟦 ВКонтакте», получает готовый шаблон поста со своей реф-ссылкой, присылает ссылку на пост (`t.me/…` или
`vk.com/…`) и скрин. Админ жмёт «✅ Принять» (+200 ₽) или «❌ Отклонить» с причиной. Одна ссылка засчитывается
один раз во всей системе: тот же пост с другого аккаунта отклоняется сразу. В «📣 Мои посты» — статус,
подтверждённые просмотры и сколько начислено, у принятого поста — «📈 Докинуть скрин просмотров»: скрин и
число просмотров. Админ видит скрин, ссылку, прошлое подтверждённое число и начисленное и жмёт
«✅ Подтвердить N» (заявленное число), «✏️ Другое число» или «❌ Отклонить».

Выплата за просмотры — нарастающим итогом: всего = ⌊подтверждённые / 100⌋ × 100 ₽, к выплате = всего − уже
выплачено за просмотры (≤ 0 — ничего, но число сохраняется). Пример: 100 просмотров → +100 ₽; потом 1000 →
ещё +900 ₽; итого за пост 200 + 1000 ₽. Подтверждённое число может только расти — меньшее бот отклонит с
подсказкой. Ограничения: отчёт по посту не чаще раза в 12 ч, не больше одного отчёта на проверке, не больше
3 активных постов у человека, потолок за просмотры на пост — 0 (без потолка). Пост удалили — «🗑 Пост удалён»:
новые отчёты по нему не принимаются. «✏️ Корректировка ₽» по посту — только 2 уровень. О каждом решении клиенту
приходит уведомление.

Ожидание ссылки или скрина не мешает остальному: ушёл клиент в меню или оформил заказ — ожидание тихо
отменяется, вернуться можно в любой момент через «📣 Мои посты».

Все заявки — в `/admin → 🎯 Задания` (счётчик — на главном экране и в утренней сводке), там же «📣 Все посты».
Суммы, шаг, лимиты, шаблон поста и перепроверка — в `⚙️ Настройки → 🎯 Задания: профиль и посты`; там же
задания можно выключить.

### 🎟 Промокоды на безлимит

`promo_codes.txt` в корне проекта — 45 кодов, которые миграция `0005` занесла в базу: разделы «Навсегда (35)» и
«30 дней (10)», один код на строку. Это секрет: файл в `.gitignore` и `.dockerignore`, на сервер его копировать
не нужно. Раздавай клиентам по одному коду; актуальный список (свободные и активированные) всегда можно скачать:
`🔐 Управление → 🎟 Промокоды → 📄 Скачать промокоды (txt)`.

- **Клиент:** «🎟 Ввести промокод» (или `/promo`) → присылает код → безлимит включается сразу. Заказ оформляет
  как обычно; в итоге заказа — «♾ Бесплатно по безлимиту», счёт не приходит.
- **Админ:** в уведомлении о заказе — «♾ Безлимит (промокод)…», в карточке вместо счёта —
  «✅ Принять в очередь (безлимит, 0 ₽)». Дальше — как с оплаченным заказом: «🛠 Взять в работу» → решение.
  Отклонить заказ можно как обычно.
- **Карточка кода:** тип, статус, кто и когда активировал, «⛔ Отозвать код». Отзыв активированного кода снимает
  безлимит у этого пользователя (заказы, которые мы ещё не приняли, — снова по обычной цене; принятые остаются
  бесплатными) и присылает ему уведомление.
- **«♾ Выдать безлимит» / «🚫 Снять безлимит»** — вручную по @username или ID, без кода: навсегда или на 30 дней.
- **Коды утекли** — отзови их и выпусти новые: «➕ Выпустить новые» → тип → количество (до 200 за раз). Файл с
  новыми кодами придёт в чат — в `promo_codes.txt` их нет, сохрани этот файл.

### Наценка за срочность

`⚙️ Настройки → ⏱ Срочность`. Считается по времени от отправки заказа до дедлайна:

| До дедлайна | Множитель | Настройка |
|---|---|---|
| 48 ч и больше | ×1,0 — без наценки | «Без наценки, если до дедлайна от, ч» = 48, «Множитель «заранее»» = 1 |
| от 24 до 48 ч | ×1,5 | «Множитель «скоро»» = 1,5 |
| меньше 24 ч | ×2,0 | «Максимальная наценка, если меньше, ч» = 24, «Множитель «срочно»» = 2 |

Всё, что видит клиент, собирается из этих цифр: подсказки на кнопках дедлайна («Сегодня · ×2,0»,
«Завтра · ×1,5», «Через 3+ дня · без наценки»), строка цены в итоге заказа, «❓ Помощь → ⏰ Сроки и цены»,
обучалка. Поменял множитель — тексты поменялись сами (в стандартном `/terms` цифр нет; если впишешь свои —
их правь сам). Бот не даст сохранить противоречие (например, порог «срочно» больше порога «без наценки»).

### Канал и бонусы за подписку

`⚙️ Настройки → 📢 Канал и бонусы за подписку`: канал (по умолчанию `@aegis_samara`, `-` — выключить), бонус за
подписку (50 ₽), бонус пригласившему (50 ₽), срок удержания (48 ч), лимит друзей в сутки (10).

**Обязательно один раз:** добавь бота в администраторы канала (канал → Управление каналом → Администраторы →
Добавить → найти бота; права достаточно минимальных). Иначе Telegram не показывает боту, кто подписан: бот
предупредит об этом при запуске в логе и на главном экране админки («⚠️ Не проверяется подписка…»).

Как работает: клиент видит предложение в приветствии, в «🎁 Подарки» и «🎁 Бонусы и акции» → «📢 Открыть
канал» → подписывается → «✅ Я подписался — проверить» → +50 ₽ бонусами. Друг, пришедший по ссылке
«👥 Пригласить друга», подписался — пригласивший получает +50 ₽ после срока удержания (и сам друг — свои
+50 ₽ за подписку).

Защита от накруток:
- бонус за подписку — один раз на аккаунт; отписался раньше срока удержания — бонус списывается и больше не
  начисляется никогда;
- друг засчитывается, только если **впервые** зашёл в бота по ссылке; себя пригласить нельзя;
- пригласивший получает бонус только после срока удержания, если друг всё ещё подписан и сам пригласивший тоже
  подписан;
- не больше 10 друзей в сутки на одного (остальные ждут следующего дня); забаненным — ничего.

## 9. Бэкап и восстановление

**Автоматически:** каждый день в `BACKUP_HOUR` (по умолчанию 04:00 по Самаре) → `data/backups/`, хранится
`BACKUP_KEEP` последних (14). Бэкап делается через SQLite backup API — корректно даже при работающем боте.

**Вручную:**
- из бота: `/admin → 💾 Данные → 💾 Бэкап сейчас` — файл БД придёт в чат;
- на сервере: `docker compose exec bot python scripts/make_backup.py` (локально — `python scripts/make_backup.py`).

Скачать бэкапы к себе: `scp root@IP_СЕРВЕРА:/opt/aegis/data/backups/*.db .`

В БД — всё про пользователей, деньги и заказы. Файлы (решения, фото) лежат рядом в `data/`, поэтому
для полного бэкапа сохрани всю папку: `tar czf aegis-data-$(date +%F).tgz data .env`.

**Восстановление** (бот обязательно остановлен):

```bash
docker compose stop bot
docker compose run --rm bot python scripts/restore_backup.py          # список бэкапов
docker compose run --rm bot python scripts/restore_backup.py latest   # последний
# или конкретный файл: … restore_backup.py data/backups/aegis-20250101-040000.db
docker compose start bot
```

Локально то же самое: `python scripts/restore_backup.py latest`. Скрипт проверяет файл
(`PRAGMA integrity_check`, нужные таблицы), сохраняет текущую БД в `data/backups/before-restore-*.db`
(откатиться — тем же скриптом) и подменяет базу. Миграции, если бэкап старой версии, применятся при запуске.

Проверка целостности: `/admin → 💾 Данные → 🩺 Проверка целостности` или
`docker compose exec bot python scripts/check_integrity.py`.

## 10. Переезд на новый сервер

1. На старом сервере: `cd /opt/aegis && docker compose stop` и упакуй проект вместе с данными:
   `cd /opt && tar czf aegis-move.tgz aegis` (внутри `data/` и `.env`).
2. Скопируй на новый сервер: `scp /opt/aegis-move.tgz root@НОВЫЙ_IP:/opt/`.
3. На новом: поставь Docker (раздел 5), `cd /opt && tar xzf aegis-move.tgz && cd aegis`.
4. В DNS поменяй A-запись домена на новый IP. **Домен и `WEBAPP_BASE_URL` оставь прежними** — тогда кнопки в
   старых сообщениях продолжат открываться.
5. `docker compose up -d --build` — Caddy сам получит сертификат на новом сервере.
6. Проверь бота и `https://домен/health`, после этого на старом сервере: `docker compose down`.
   Два запущенных бота с одним токеном мешают друг другу — старый должен быть остановлен.

4. Вкладка **Данные** (Browse Data) → выбери таблицу:

## 13. Сценарий проверки на двух аккаунтах

Нужны два Telegram-аккаунта: **Аккаунт 1** — твой (его id в `ADMIN_IDS`), **Аккаунт 2** — любой другой
(второй телефон или «Добавить аккаунт» в настройках Telegram). Режим оплаты — 🧪 тест, цены по умолчанию.
**Перед началом:** `/admin → ⚙️ Настройки → 👥 Рефералка и бонусы → «Бонус за друга с оплаченным заказом»` →
`50` (во второй версии по умолчанию 0 — бонус за друга дают за подписку на канал; без этого шаги 5 и 7 пройдут
без бонуса). Этот же сценарий автоматически прогоняет `pytest tests/test_e2e_scenario.py`.

1. **Аккаунт 2 заходит по реф-ссылке аккаунта 1, получает подарки, открывает тренажёр.**
   Аккаунт 1: `/start` → «👥 Пригласить друга» → скопируй ссылку `https://t.me/бот?start=ref_…` и отправь
   аккаунту 2. Аккаунт 2 открывает ссылку → «Запустить» → приходит приветствие, в конце которого
   «🎁 Тебе подарки — бесплатные материалы:» и три ссылки (расчётка, начерталка, матрицы) — без кнопок, и
   короткая обучалка (её можно пролистать или «Пропустить») → нажимает ссылку на тренажёр — он открывается в
   браузере. Аккаунту 1 приходит «👥 По твоей ссылке зашёл новый друг!».
2. **Аккаунт 2 оформляет заказ: начерталка, 1 задача, дедлайн через 4 дня, фото лекции и практики.**
   «📝 Заказать» → «📐 Начерталка» → фото условия → «✅ Готово» → «1» → «Без варианта» →
   «Через 3+ дня · без наценки» → дата через 4 дня → фото лекции → «✅ Готово» → фото практики → «✅ Готово» →
   «⏭ Без комментария». В итоге: `💵 200 ₽ × 1 задача = 200 ₽ · срок без наценки` и
   «📚 Если конспекты пройдут проверку: −50% → 100 ₽».
   «🚀 Отправить» → «✅ Принимаю условия» → «✅ Заказ #1 отправлен на проверку».
3. **Аккаунт 1 видит заказ, одобряет оба конспекта → 100 ₽ → выставляет счёт.**
   Приходит «📥 Новый заказ #1…» → «📦 Открыть заказ» (или `/admin → 📥 Заказы`) → «✅ Лекция» →
   «✅ Практика» → кнопка меняется на «💳 Выставить счёт · 100 ₽» → нажми.

   «💳 Заказ #1 проверен. К оплате: 100 ₽» → «💳 Оплатить · 100 ₽» → «💳 Оплатить (тест)» →
   «✅ Оплата прошла!». Аккаунту 1 — «💰 Оплата заказа #1 … 🧪 тест».
5. **Аккаунт 1 берёт в работу, загружает HTML-решение, «Готово» → ему +50 бонусов за друга.**
   «📦 Открыть заказ» → «🛠 Взять в работу» → «📤 Загрузить решение» → отправь `.html` **файлом**
   (скрепка → Файл) → «💾 Сохранить (1)» → «📦 Готово — отправить клиенту». Аккаунту 1 приходит
   «🎉 Твой друг получил первый оплаченный заказ — тебе +50 ₽ бонусами», в карточке заказа —
   «👥 Пригласившему … начислено +50 ₽ бонусами».
6. **Аккаунт 2 открывает решение, жмёт «Не зачли» и присылает скрин.**
   «📦 Решение по заказу #1 готово!» → «🧩 Открыть решение» → «❌ Не зачли» → пришли фото. Аккаунту 1
   приходит «❌ «Не зачли» по заказу #1» и сам скрин с кнопками «🔁 Переделать» / «↩️ Вернуть деньги».

   «↩️ Вернуть деньги» → экран показывает «вернётся 100 ₽» и «Бонус пригласившему (50 ₽) будет отозван» →
   «↩️ На баланс». Аккаунт 2: «↩️ Возврат по заказу #1: 100 ₽ — на рублёвый баланс», «💰 Баланс» → 100 ₽.
   Аккаунт 1: «Заказ друга вернули… −50 ₽ бонусами», его баланс бонусов — 0 ₽.
8. **Статистика, карточки и CSV сходятся.**

   `🩺 Проверка целостности` → «Всё сходится».
